# 入札「物品の売買」規格適合商品サーチ（Google AI モード用プロンプト）v0

海上自衛隊 横須賀地方総監部の入札公告（物品の売買）について、**仕様書・内訳書の規格を読み取り、楽天市場・Yahoo!ショッピング・Amazon から規格に合う商品を探す**ための、Google AI モードに貼り付けて使うプロンプト一式。

- `prompt.md` … AI モードに貼る本体（固定ルール＋入力フォーマット＋出力フォーマット）
- 本 README … 設計の前提と、食品規格書の扱いについての判断

---

## 1. 前提：AI モードで「動くもの」は何か

AI モードはコードを実行しない。動かせるのは **構造化されたプロンプト** と **添付ファイル（画像・PDF）** だけ。
したがって「アプリ」の実体は次の3層に分かれる。

| 層 | 中身 | 変わる頻度 | どこに置くか |
|---|---|---|---|
| ① 固定ルール | 規格の分解方法、適合判定基準、出力表の形、禁止事項 | ほぼ不変 | プロンプト冒頭（毎回貼る） |
| ② 準固定の参照資料 | 食品の規格書 | 年度・改定ごと | **都度、該当品目分だけ渡す**（→ 3章） |
| ③ 案件データ | 仕様書・内訳書・価格帯 | 案件ごと | 入力フォーマットに記入 or 添付 |

## 2. 壊れやすい箇所（先に潰しておく前提）

1. **URL・価格の捏造**：AI は「ありそうな」商品ページを作文しうる。→ 実際に検索結果で確認できたものだけを載せ、確認できなければ「未確認」と書かせる。
2. **単位のずれ**：内訳書は「1袋」「1kg」「1箱(24本)」等、通販は「500g×2」「12本×2ケース」等。→ **内訳書の単位あたり単価に換算**させ、価格帯判定はその換算値で行う。
3. **「同等品」の判定の甘さ**：銘柄指定＋「又は同等品」の場合、何をもって同等とするかを必須要件として先に書き出させる。
4. **件数過多による精度劣化**：内訳書が数十品目あると後半ほど雑になる。→ **1回 5〜10 品目**に分割して投げる運用。
5. **Amazon の価格取得の弱さ**：AI モードはショッピング情報（楽天・Yahoo）は拾いやすいが、Amazon は価格が取れないことがある。→ 取れない場合は検索キーワードと「要目視確認」を返させる。

## 3. 食品規格書は「預けておく」か「都度渡す」か

**結論：AI モードでは都度渡す。ただし全文ではなく「今回の品目に該当する規格だけ」を抜粋して渡す。**

理由（構造的なもの）:

- **AI モードには資料を保持する仕組みがない**。前の会話の添付を確実に参照し続ける保証がなく、「預けたつもり」が最も危険。
- **黙って古い規格が使われる事故を防げる**。規格書は改定されうる。常駐させると改定後も旧版で判定され続け、しかも誰も気づかない。都度渡しにすると、入力欄の「規格書の版・年度」が毎回明示される。
- **全文を渡すと精度が落ちる**。無関係な品目の規格がノイズになり、取り違え（例：別品目の内容量・等級を適用）が起きる。

例外：品目数・頻度が多く、毎回の抜粋が負担になる場合は、**Gemini の Gem**（カスタム指示＋知識ファイルを保存できる）に ①固定ルールと②規格書を置き、③だけ毎回入れる構成に移行するのが合理的。トレードオフは「通販横断の商品検索力は AI モードの方が強い」こと。

## 4. 使い方

1. `prompt.md` の「固定ルール」〜「出力フォーマット」までをそのままコピー。
2. 「入力フォーマット」部分に案件データを記入（仕様書・内訳書は PDF 添付でも可）。
3. 食品が含まれる場合は、該当品目の規格を規格書から抜粋して【食品規格】欄に貼る（または該当ページの画像を添付）。
4. AI モードに貼り付けて送信。品目が多い場合は 5〜10 品目ずつ。
5. 出力の URL・価格は**必ず実ページで目視確認**（AI の出力は候補リストであって確定情報ではない）。
